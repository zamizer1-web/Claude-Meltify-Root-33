# Root 33 core: the contract for character builders

`src/Root33.Core` holds every rule of Root 33 with no engine reference (netstandard2.0, C# 9, warnings are errors). It never touches Root directly:

- it **reads** the board through `IBoardView` (one member per `sheets/board_reads.json` row),
- it **changes** the game through `IBoardActions` (one member per `sheets/board_actions.json` row),
- it **is driven** through `IGameHooks` (one member per `sheets/game_hooks.json` row).

These three interfaces, `ModState` (one field per `state.json` row), `Tuning` (one constant per `tuning.json` row), `Sheets.Data` (every sheet row) and `Sheets.Ids` (every row id) are generated by `python3 -I tools/gen_cs.py` into `src/Root33.Core/Generated/`. Never edit those files; change the sheet and regenerate. The plugin written later on the creator's PC implements `IBoardView` and `IBoardActions` on top of Root and calls `Root33Game`'s hooks from Harmony patches.

The sheets are the source of truth. When a row is wrong or unclear, do not invent a rule: report the question.

## Layout

```

  Generated/*.g.cs                                generated from the sheets (do not edit)

  State/SpawnStates.cs                            RockState and FootState fields (state.esquie.rocks, state.monoco.feet)
  Engine/GameContext.cs                           everything a module may use during a game

  Engine/ICharacterModule.cs                      ICharacterModule, CharacterModule (no-op base), HookOrder
  Engine/IWinCondition.cs                         IWinCondition, WinConditionBase, WinRules (gates and timing)
  Engine/IBotDirector.cs                          IBotDirector, BotView, PublicBoardView, [BotRule], Ranked<T>
  Engine/ModuleRegistry.cs                        character id -> module factory; Default() finds every module
  Engine/RoleMap.cs, AutumnMap.cs                 map roles (map_roles.json, map_autumn.json)
  Characters/<Name>/<Name>Win.cs                  one character's win condition      (character builders)
  Characters/<Name>/<Name>Tweaks.cs               its rule tweaks and spawns          (character builders)
  Characters/<Name>/<Name>Bot.cs                  its bot director                    (character builders)
  Characters/<Name>/<Name>Module.cs               the module that ties them together  (character builders)
src/Root33.Core.Tests/

```

`<Name>` is the PascalCase character id: `Gustave`, `Esquie`, `Paintress`, `Sciel`, `Verso`, `Maelle`, `Lune`, `Monoco`, `Curator`, `Clea`, `WhiteHairedMan`. Use the namespace `Root33.Core.Characters.<Name>` (tests: `Root33.Core.Tests.Characters`). Keep everything about one character inside its folder; when you need a shared helper, add it next to the framework and say so.

## A character module

```csharp
namespace Root33.Core.Characters.Gustave
{
    public sealed class GustaveModule : CharacterModule           // public, parameterless constructor
    {
        public override string CharacterId => CharacterIds.Gustave; // characters.json id
        public override int Order => HookOrder.Gustave;            // see "Hook order" below
        public override IWinCondition Win { get; } = new GustaveWin();
        public override IBotDirector Bot { get; } = new GustaveBot();

        // Rule tweaks and spawns: override only the hooks the rows name, and delegate to GustaveTweaks.
        public override void OnEveningEnd(SeatId seat) { if (IsMe(seat)) GustaveTweaks.PlantFlags(Ctx, Seat); }
        public override void OnBattleResolved(BattleResult r) => GustaveTweaks.ChargeArm(Ctx, Seat, r);
        public override void OnStateLoaded(IReadOnlyCollection<string> loadedKeys) => GustaveTweaks.RecheckOnLoad(Ctx, Seat, loadedKeys);
    }
}
```

**Registering.** Nothing to do: `ModuleRegistry.Default()` finds every non-abstract `ICharacterModule` with a public parameterless constructor in Root33.Core, and `new Root33Game(board, actions)` uses it. Tests can register exactly the modules they want: `new ModuleRegistry().Register("gustave", () => new GustaveModule())`.

**Lifetime.** `Root33Game` creates one module instance per seated character at hook.game-start (and again at hook.load) and calls `Bind(ctx, seat)`. Inside a module, `Ctx` is the `GameContext`, `Seat` its own seat, and `Board`, `Actions`, `State` are shortcuts. Because a load re-creates the modules, **everything that must survive a save lives in `ModState`**, never in module fields. If a value you need has no `state.json` row, report it as a question; do not add hidden state.

**Handlers see every seat.** Every hook goes to every module. Compare the seat argument with `Seat` (`IsMe(seat)`) when a rule is about the character's own turn, and read the other seats' events when the rule reacts to them (for example a guard counter dropping when a host warrior dies in someone else's battle).

**Veto hooks.** `CanStartBattle` (hook.battle-legal) and `AllowHostile` (hook.hostility-change) return true by default; the game allows the action only if every module allows it.

**Story events.** At setup (Act I) and when an act opens, `Root33Game` walks that act's `events` in acts.json order. An event fires only when its tier allows it (safe: always; act2: either mode; finished: finished mode only) and, if it has an `owner` (story_events.owner), only when that character is seated. An owned event goes to its owner's `OnStoryEvent` (Gustave's module handles the Beach); a table-wide event (owner null) goes to every module. Every fired event is logged in `Ctx.StoryLog` for the plugin to show. No act event may change VP, charges, rank or relationships (`Acts_ActEventsNeverChangeVpChargeRankOrRelationships` runs every registered module).

## Hooks: what runs when

`Root33Game` implements `IGameHooks`. Nothing runs in a plain Root game: only a game created from the mod's character select (`state.global.e33-mode`) is an E33 game, and after a themed win is declared (`Ctx.GameOver`) later hooks change nothing.

| Hook | Shared systems (in this order) | Modules |
|---|---|---|
| hook.character-select | hides the Clockwork bots, starts an E33 game setup | none bound yet |
| hook.seat-assigned | records the seat's character (the mod's pick, or the one character of that engine) | none bound yet |
| hook.game-start | `ModState.Reset()`, copies difficulty, spoiler mode, Faithful Gustave, Monolith Barrier, campaign, seat characters; binds modules | `OnGameStart` |
| hook.map-loaded | assigns roles now on Autumn, or on any map when Gustave is not seated | `OnRolesAssigned`, `OnMapLoaded` |
| hook.piece-placed | Gustave's keep on a non-Autumn map assigns the roles (Lumière = the keep's corner) | `OnRolesAssigned`, `OnPiecePlaced` |
| hook.setup-complete | roles by rule if still missing, campaign journal (+1 card), **Act I story events** | `OnStoryEvent`, `OnSetupComplete` |
| hook.round-start | `state.global.round` (Root's own counter wins when it has one) | `OnRoundStart` |
| hook.birdsong-start | **countdown confirm for that seat first**, then pending VP is paid | `OnBirdsongStart`, then the bot's `PlanTurn` |
| hook.evening-start | pending draws are added | `OnEveningStart` |
| hook.evening-end | after the modules: **the seat's themed-win test** (countdown announce or quest win) | `OnEveningEnd` first |
| hook.turn-end | after the modules: **the act clock**, at most one step; a new act raises hook.act-change | `OnTurnEnd` first |
| hook.act-change | act banner, that act's story events | `OnStoryEvent`, then `OnActChanged` |
| hook.bot-decision | only for a bot seat; an answer that is not legal becomes null (Root's AI decides) | the bot's `ChooseAction` |
| hook.save | `ModState.ToText()` (empty for a plain Root game) | none |
| hook.load | restores state and applies the global `onLoad` rules (round, act, seat engines, roles) | `OnStateLoaded`, then countdowns are re-confirmed |
| every other hook | none | the matching handler |

**Hook order between modules.** Modules run in ascending `Order`, ties by seat. hook.evening-end needs Gustave's flags (`HookOrder.Gustave` = 10) before Esquie's Soarrie hand-off and early-Urrie check (`HookOrder.Esquie` = 20); everyone else uses `HookOrder.Default` (50). The win check runs after every module, so a rock handed over in Esquie's own evening-end counts that turn.

## Win conditions

Derive from `WinConditionBase` and pass the row id. It reads `kind`, `actMin`, `vpMin`, `offWithDominance` and `offInCoalition` from the row (`Row` holds the whole row, `Row.Params` its tuning keys). Implement only the themed part of the test:

```csharp
public sealed class GustaveWin : WinConditionBase
{
    public GustaveWin() : base("win.gustave") { }
    public override bool Announce(GameContext ctx, SeatId seat) => /* Arm full, ruled flagged Chain... */;
    public override bool Confirm(GameContext ctx, SeatId seat) => /* defaults to Announce: override when the row's confirm differs */;
}
```

`WinRules` applies the gates (act >= actMin, Vp >= vpMin, no active dominance when offWithDominance, no coalition partner when offInCoalition) before calling your test, at announce, at confirm and for quests, and handles the timing: countdown announce at the end of the owner's turn puts the seat in `state.global.countdowns` and shows the banner (`do.show-banner`); at the owner's next Birdsong the confirm either declares the win (`ctx.DeclareWinner`) or clears the banner. A quest win (`QuestComplete`) is declared at the end of the owner's turn. A loaded game keeps a banner only if the confirm still passes on the loaded board. Do not call `DeclareWinner`, `ShowBanner` or `ClearBanner` from a win condition yourself; return true or false.

Easy assists (a human Verso at rank A) belong inside the themed test: check `ctx.Board.IsBot(seat)` and `ctx.Difficulty`.

## Bot directors

Implement `IBotDirector` in `<Name>Bot.cs`:

- `PlanId`: the bot_plans id (`"bot.gustave"`).
- `InGoalMode(view)`: the row's `goalModeTrigger`, per difficulty (`view.Difficulty`; the `easy` / `normal` / `hard` columns).
- `PlanTurn(view, state)`: called at the bot's own Birdsong, after countdown confirmation. The only director method that writes state (routes, targets, family picks in `ModState`).
- `ChooseAction(view, legalActions)`: one of the legal action keys, or null to let Root's own AI decide.

**One bot_rules row = one public method**, named after the row's name part in PascalCase (`bot.gustave.01-route` is `Route`, `bot.esquie.05-endgame` is `Endgame`) and marked with the row id:

```csharp
[BotRule("bot.gustave.01-route")]
public List<Ranked<ClearingId>> Route(BotView view) { ... }
```

Rule methods are pure: they take a `BotView` (plus plain arguments) and return a ranking (`Ranked<T>`, highest score first; build one with `Rank.Clearings` or `Rank.Descending`, ties toward the lower clearing number) or a decision. They never call `IBoardActions`. `BotView.Board` is a `PublicBoardView`: reading another seat's hand, Alliance supporters or hidden Corvid plots throws, and face-down relic values read as null, so a bot can only use what a player in its seat could see. `ModuleRegistry.MissingBotRules(director)` lists the plan's rows that have no `[BotRule]` method yet; assert it is empty in your tests.

## GameContext

| Member | Use |
|---|---|
| `Board`, `Actions`, `State` | the board, the actions, the saved state |
| `Act`, `Round`, `Difficulty`, `Spoilers`, `Options` | game facts; `Options` holds the opt.* choices for this game (Faithful Gustave and the Monolith Barrier read state.global.faithful-gustave / monolith-barrier, so a loaded game keeps them) |
| `RuleOn(ruleTweakId)`, `UpdateRules` | whether a rule_tweaks row acts: v1 rows always, v1.1 rows only while the internal `GameOptions.UpdateRules` setting is on (off in the first release, never shown to players; tests turn it on with `TestTable.Start(..., updateRules: true)`) |
| `CharacterOf(seat)`, `SeatOf(character)`, `IsSeated(character)`, `IsVagabond(seat)` | seats and characters |
| `Role(roleId)`, `RoleClearings(roleId)`, `HasRole(c, roleId)`, `MonolithNeighbours()` | map roles; pass `Ids.MapRoles.*` |
| `HighestVp()`, `MonolithNumber`, `CompletedRoundsAfterTurnOf(seat)` | scores and the act clock's inputs |
| `ScoreVp(seat, vp)`, `DrawCards(seat, n)` | do.score-vp and do.draw-cards with their sheet fallbacks (queued in pending-vp / pending-draws) |
| `DeclareWinner(seat, winId)` | used by `WinRules`; ends the game for the core |
| `SupportsAction(boardActionId)` | whether the plugin can do a board action; when it cannot, take that row's `fallback` |
| `Countdown`, `ActClock`, `StoryLog`, `Warnings` | shared systems and logs |

Use `Ids.*` constants and `Tuning.*` constants, never literal ids or numbers that a sheet already holds.

## Testing with FakeBoard

`FakeBoard` implements `IBoardView` and `IBoardActions` with plain collections. `FakeBoard.Autumn()` is the real Autumn map from `sheets/map_autumn.json`: clearing `autumn.NN` is clearing `NN` (until Root's own ids are known), with suits, slots, paths, river, ruins, corners, Continent names and fixed roles. Address a clearing by number, id, role or Continent name: `b.C("The Monolith")`, `b.C("role.monolith")`, `b.C("autumn.03")`, `b.C(3)`, and every builder method takes those strings too.

```csharp
var board = FakeBoard.Autumn()
    .Seat(0, EngineId.Marquise, "gustave")                 // seats in turn order; character optional
    .Seat(1, EngineId.Eyrie, "paintress", bot: true)
    .Warriors(0, "Lumière", 3)                            // absolute count
    .Building(0, "Lumière", PieceTypes.Sawmill)           // adds one; RemoveBuilding removes one
    .Token(0, "Lumière", PieceTypes.Keep)
    .Building(1, "The Monolith", PieceTypes.Roost).Warriors(1, "The Monolith", 2)
    .Vp(0, 12).Dominance(1, null).Hand(1, Suit.Fox, Suit.Bird);

var t = TestTable.Start(board, new ModuleRegistry().Register("gustave", () => new GustaveModule()));
t.PlayTurn(0);                       // round start (first seat), Birdsong, Evening start, Evening end, turn end
t.PlayTurn(1, during: x => x.Game.OnBattleResolved(result));
var loaded = t.SaveAndLoad(registry); // hook.save then hook.load into a fresh Root33Game on the same board
Assert.Equal("win.gustave", board.Banners[new SeatId(0)]);
```

- Rule in the fake: the most warriors plus buildings rules (at least one piece); a tie rules nobody, except that the Eyrie rules a tie it is part of; a Lizard garden always rules. Tokens and pawns never count.
- Other maps: `FakeBoard.Map("winter").Clearings(12).Corners(...).Paths("1-2 2-3").Ruins(...).Opposite(a, b).River(a, b).ClosedPath(a, b).Forest(n, ...)`; `MapNamed("winter")` runs the role rules on the Autumn graph.
- Everything else Root shows: `Pawn`, `PawnInForest`, `Item`, `Relationship`, `Coalition`, `Supply`, `SupplyOf`, `Relic`, `CarryRelic`, `RecoverRelic`, `DropRelic`, `FaceUpPlotAt`, `HiddenPlotAt`, `Column` (Decree, Retinue), `SupportersAre`, `Burrow`, `Ministers`, `Outcast`, `MoodIs`, `Hoard`, `Legal`, `RuinEmptied`, `RootRound`.
- Every action applies to the board and is logged: `Log`, `Winners`, `Banners`, `ScoredVp`, `Draws`, `ExtraHits`, `ExtraMaxHits`, `IgnoresFirstHit`, `GuardFloors`, `BlockedPlacements`, `HomeRestrictions`, `StartForestRestrictions`, `Abilities`, `Bubbles`, `Overlays` (`OverlayShown(id)`), `SeatTitles`, `SubmittedActions`, `NativeAiSteps`, `TaggedRelics`, `FreeDigs`. `PlaceWarriors` takes from the seat's supply and returns how many it placed.
- Fallbacks: `board.Unsupported(Ids.BoardActions.PlaceWarriors)` makes that action do nothing, and `TestTable` tells the game it is unsupported, so `Ctx.SupportsAction` is false and your fallback path runs.
- The river links (`map_autumn.riverLinks`: 1-6, 6-7, 7-10, 10-11) and the diagonal corner pairs (`oppositeCorner`: 1-3, 2-4) come from the sheet. Only the seven forests have no sheet column yet, so the fake takes them from `design/autumn-map-verified.json`, numbered 1-7 here as the faces the printed paths enclose. Root's own forest numbers are still unknown; do not hard-code them in rules.

**Tests.** Every `tests` cell of your rows names xunit methods: write each as a `[Fact]` with exactly that name in `src/Root33.Core.Tests/Characters/<Name>Tests.cs`, and make it prove what the row says. A row is finished only when its named tests exist and pass. Run everything with:

```
export PATH=/root/.dotnet:$PATH DOTNET_CLI_TELEMETRY_OPTOUT=1 DOTNET_NOLOGO=1
dotnet test src/Root33.sln
```

## Save format

`ModState.Save()` returns one entry per `state.json` row, keyed by the row id (`state.global.act` = `3`). Values are invariant text with no JSON: lists `1,6,11`, maps `0=gustave;1=paintress`, records `guarded|6|3|2`, null `~`, strings %-escaped. `ModState.ToText()` writes a `root33-state 1` header and one `key=value` line per entry; hook.save returns it. `Load()` resets first, restores every entry it can read and returns the keys it loaded, so a module's `OnStateLoaded` can apply its row's "if the save has none" rule. Each row's other `onLoad` checks (clamping, dropping clearings not on the map, re-checking against the board) belong to the module that owns the row.
